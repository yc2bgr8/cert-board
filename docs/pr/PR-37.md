# PR-37 模型正式比选

按执行方案先准备 K14 的公开回放底稿。独立验收虚拟机可以执行 `pnpm k14:collect A 2026-11-25` 或 `pnpm k14:collect C 2026-11-25`。只读取计划中的官方来源。每次采集生成独立目录，原始响应、索引、来源地址、获取时刻、大小和 SHA-256 保存在本机 `.local/k14/`。运行 `pnpm k14:verify <档案编号>` 离线重新校验并重算索引。

- A 收集 FDA 四个产品代码从 2016 年以来的 SESE 决定，核对 API 总数和实际记录。2026 年候选的公开摘要按 K 号请求并记录取得状态。
- C 收集 MDALL 活动许可，再按「许可号、器械编号」连接器械及型号标识。不同许可内可能出现同一个器械编号。按各自首次加入日期截去晚于指定日期的记录。活动状态对应本次公开快照。
- `pnpm k14:collect C-history <截至日期> <集 C 活动档案编号>` 从相同 MDALL 接口读取历史状态。索引保留取消许可、被移除的器械与型号标识，覆盖名称命中的历史许可及活动档案中的许可。记录官方公布的加入和终止日期，排除晚于截止日的终止事件。历史档案引用同一截止日的活动档案，通过清单的 SHA-256 绑定。两份档案均须保留，`pnpm k14:verify <历史档案编号>` 会校验两份原始记录并重算索引。
- 两地的 2026 年候选只供挑选。正式评测还要核对每个模型的训练截止日期、准备及审阅题目，并走 PR-35 的遮挡、时间截断和偷看检测。原始索引带公开编号，供本地题目构建使用。

历史档案反映采集时 MDALL 公布的终止记录。用来制作回放题时，仍须按题目时间核对可见字段。涉及同名产品、资质状态或归属不清的记录需要人工抽查。

构建仓库的 Docsvc 测试镜像后，`pnpm k14:extract-a <集 A 档案编号>` 用无网络容器逐页解析原件。结果另存为 `.local/k14-pages/`，记录原件与逐页文件的 SHA-256、物理页码、解析方式和空白页。原件缺失和解析失败在清单分开记录。

## 跨市场核对

`pnpm k14:pair <集 A 档案编号> <活动集 C 档案编号>` 对同一截止日的两份已验证档案做名称初筛，按许可和器械编号取得型号标识。归档相关 MDALL 公司回执、FDA 510(k) 摘要和同一申报号的 GUDID 回执。UDI 只纳入公布日和公开版本日都在截止日期内的记录，分别保留型号、目录号和商品名证据。输入清单与新增来源均以 SHA-256 核对。禁网环境可用 `pnpm k14:verify-pairs <配对档案编号>` 重算索引。

同名、公司名称相符或型号相符只记为候选证据。注册人员需要确认主体、型号及申报范围后，才能选入评测题。现场核对见 [K14 跨市场核对表](../evidence/K14-公开回放底稿.md#跨市场同名候选核对)。

本轮已校验的集 A、C 数量及解析覆盖见[K14 公开回放底稿](../evidence/K14-公开回放底稿.md)。
