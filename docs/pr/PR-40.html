PR-40 网页工具、证据存档与隔离抓取

按执行方案 v0.4 PR-40、技术方案 v0.4 §4.17、v2 §1.4 和附录 B.3 实施。

做了什么

  • Agent 的 web_search 返回有界的地址、标题、摘要和来源类别。web_fetch 在只读会话提供临时预览，在可写会话检查资料写权限后存档，返回资料编号、版本和首段摘要。网页和检索结果均作为不可信资料处理。
  • 抓取服务、抓取代理和固定中继分段部署。代理只接收 HTTPS CONNECT 到 443 端口，拒绝私有、回环、链路本地和保留地址。对外请求在后端先检查保密词和已有保密原文重合，保密项目或对话整条路径关闭。
  • 同一运行检索、抓取合计最多八次，同项目、同地址保留 24 小时缓存。原件以 SHA-256 核对，按项目资料版本保留来源类型、地址和北京时间。解析文本经 doc_read 参与 V1，证据面板提供受 Cookie 保护的本地下载，原件以附件发送。

验收

  • pnpm test:py 在无网络的测试容器验证地址限制、完整性、总时限、字符编码、Unicode 长度、哈希、检索结果及未启用回退。
  • pnpm test:int apps/backend/src/tools/web-tools.int.test.ts 覆盖资料入库和读取、只读无存档、跳转提示、缓存过期、预算、抓取失败、哈希与 PDF 原件。
  • pnpm lint、pnpm typecheck、pnpm test 和 Vite 构建覆盖通用检查、网页和 PDF 下载入口，以及抓取客户端协定。
  • pnpm eval:agent 的 30 项同内核剧本通过。
  • pnpm dev:fetcher:up 后通过独立代理抓取公开的 OpenRouter 目录 GET，原件 36,546 字节并生成哈希。抓取服务和代理对回环地址都返回 403。抓取容器仅加入专用网络，直连数据库端口失败。
  • pnpm dev:isolated:web:up 启动隔离部署。浏览器端口 28186 和 worker 到固定中继的健康检查返回 200，容器抓取中继无宿主端口。日常工作台 28080 返回 200。

没做什么

  • 自建检索服务联调等待部署。SearXNG 标准 JSON 协议用测试服务验收，开发默认关闭，可独立抓取已知网址。检索协议（外部链接）
  • PDF 已归档，解析正文和逐页引用依赖 PR-17；二进制原件直接复制进工作副本等待配套文件工具。网页资料的解析片段可通过资料工具读取。
  • 外部结论的出处逐字校验、本地模型出网复核和相关审核展示由 PR-D5 接入。开发机的 Fake-IP 可能影响部分公开站点，联调核对公共 DNS。检索词的审计取舍见 D-043。

本 PR 无真实模型调用，模型费用 0 美元。引入 Python 3.12（PSF-2.0）、uv 0.13.9（Apache-2.0 或 MIT）、FastAPI 0.165.0（MIT）、Uvicorn 0.54.0（BSD-3-Clause）和测试依赖 pytest 9.2.0（MIT），使用固定镜像摘要和 uv.lock 校验。依赖在构建时从镜像与包仓库下载。运行时无遥测集成，测试容器无网络。抓取运行时关闭访问日志，代理日志只保留请求方法、目的域和端口、状态以及时间。uv 镜像集成（外部链接）
