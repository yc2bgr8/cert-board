PR-45 R01 立项计划与 R02 路径研判

本机候选范围

  • 供注册人员审阅的 R01、R02 技能草稿可用现行 skill:stage 登记。R01 区分目标日期、候选时间和有出处的实际事件。R02 引导分类、路径和编号回查，分开候选与正式审核决定。
  • work_schedule_calculate 接受人员提供的目标日期、节点、负责人、日历日工期和依赖，计算最晚安排、关键路径及起始限制下的可行性。没有已知起始条件则待确认。它只计算计划，原有项目事实和工作区通过现有入口操作，法定期限另走期限工具。
  • cert_context 提供两个技能所需的当前项目、目标、方向和待处理数量。默认按本轮项目读取；可以分页读取本人负责的项目与目标。回放时重新核对归属及资料级别。
  • E01 至 E03 的判分数据用 FDA 官方记录核对。E23 的实际日期保留报表字段或 FDA 接收和决定字段的出处。日期语义以实际报表字段为准，立项、送样、付款和草稿报告仍保持缺少证据。FDA LRK（外部链接） · FDA L08 记录（外部链接） · FDA SnoreRx（外部链接）

开发验收

  • pnpm eval:r01-r02 核对技能草稿元数据、原文逐页出处、倒排、并行依赖、闰日、关键路径、不可行目标及无效前置关系。E23 用 Agent 剧本读取合成资料并判分实际交付内容，覆盖交换日期和编造缺证据节点。判分表中的申报类型和接收日期与 FDA 官方案卷字段摘录逐项核对。
  • 隔离虚拟机的类型、lint、9 项专项和 35 项 Agent 剧本通过。维护目录的初次集成用例错绑了注册项目，被数据库拒绝。按正常项目类型建立独立维护项目后，目录对照和调用前后业务状态比对通过。两个草稿分别按完整路径登记两次，实际数据库各保留一份 0.1.0，发布记录为零。
  • 本轮新增两个集成场景。第一项逐级验证项目隔离、本人分页范围和密级提升及负责人变更后的回执重验。第二项在隔离测试库从浏览器审阅两个技能，再在空白项目中用已登记工具执行 R01 倒排和 R02 补缺。信息待确认时通过 ask_user 等待发起人回答。

没做什么

  • Agent 直接创建新项目、业务计划节点持久化及改期差异联动仍待完成。现在由注册人员在浏览器建立项目，Agent 将倒排计划作为工作区交付。
  • 正式市场规则包与技能发布依赖 PR-42。用受控设计资料完成真实模型的 L08 分类与路径回放、20 例 pd 评测和 CPAP 的注册人员评审均待完成。
