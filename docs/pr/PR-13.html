PR-13 出网代理与网络分段

按执行方案 v0.4 的 PR-13、技术方案第 2.2、10.1 节，以及 v2 变更单第 1.4、1.5 节和附录 B.3 实施。容器部署使用独立的 cert-board-isolated Compose 项目和命名卷。

做了什么

  • API、Agent worker、数据库和对象存储在隔离的内部网段。浏览器只经过发布到回环地址的 Nginx 入口。API 与 worker 没有宿主端口，模型网关在容器内只接受 http://egress:3128。
  • 内部业务和沙箱分别连接独立的 Squid 入口。业务代理允许执行方案的四个主机；沙箱代理允许 v2 列出的官方域名和 Python 包下载源。两个代理仅接受白名单域名的 HTTPS CONNECT，拒绝私网、回环和保留地址。主模型仍使用自己的精确模型白名单。代理无业务凭据。
  • 解析、沙箱与抓取的测试容器分别加入各自网段。开发中继只在入口网卡监听，转发至三个固定测试目标。默认启动容器工作台时没有这些测试入口。
  • Docker 构建仅复制应用、依赖清单、已登记 Agent 和技能以及部署配置。开发密钥、原始资料、测试快照及本机构建产物从上下文排除。
  • Windows 日常开发继续使用回环 API 和 127.0.0.1:28085 代理。Windows 上的 Cursor 核实仍沿用 v4 的受限宿主进程。容器工作台显示该通道暂不可用，并阻止创建核实请求。Windows 开发模式的出网约束来自程序和代理配置，容器模式另外用网络结构隔离。
  • 容器发布端口与 API 可信浏览器来源由同一个回环配置派生。隔离项目可从 .env.local 的现有开发账号配置创建账号，口令通过标准输入传入种子进程。

在独立环境验证

$env:CERT_ISOLATED_WEB_PORT='28186'
pnpm dev:isolated:up
pnpm test:network

pnpm test:network 启动单用途的无凭据探针和开发中继，并用 Chrome 或 Edge 验证 28186 的登录、带会话的对话写入及 Cursor 拦截。它核对实际 Docker 网络和端口，验证 API 与 worker 直连公网失败、通过 Squid 可建立验证了证书的 TLS、非白名单被拒、沙箱和抓取网段无法直连 PostgreSQL、其他网段无法利用探针中继访问内部服务，以及本机经三个固定端口可访问对应探针。不会触发模型推理。

本机 Docker 29.9.3 实测通过。API 和 worker 经业务代理验证 OpenRouter 证书。沙箱经专用代理验证 pypi.org 和 files.pythonhosted.org 的证书，并确认模型代理、未列入的主机、数据库 IP 与中继的内部监听均被阻断。解析、沙箱和抓取的三条固定回环转发返回各自的健康响应。外部 DNS 探针在三个隔离网段均失败。探针故意携带模拟的数据库连接变量时也会拒绝运行。

在隔离验收项目中临时撤销 pypi.org 后，用平时的启动命令重建代理。确认沙箱代理镜像更新，对原域名返回 403，然后还原白名单并重新验证。

本地 pnpm lint、pnpm typecheck、pnpm test、pnpm test:int、pnpm eval:agent、隔离端口 pnpm test:e2e 和 pnpm docs:html 通过。覆盖 422 项单元测试、435 项集成测试、59 项浏览器检查和 30 项 Agent 剧本。新增真实模型调用 0 次，新增模型费用 0 美元。

wsl -d Ubuntu-24.04 -- docker logs cert-board-isolated-egress-1
wsl -d Ubuntu-24.04 -- docker logs cert-board-isolated-sandbox-egress-1

代理日志可导出，仅含时间、方法、域名、端口、状态和结果码。依赖状态用 pnpm dev:isolated:status 查看，pnpm dev:isolated:down 只关闭隔离项目并保留卷。Windows 日常入口为 28080，隔离验收使用 28186。可单独用 pnpm dev:isolated:accounts 初始化隔离库的开发账号。

没做什么

  • 解析、沙箱执行与抓取服务分别由 PR-17、PR-22 和 PR-40 接入。PR-13 用无凭据的测试服务验收网段和固定中继。
  • 本机 Fake-IP 会让部分已批准官方域名暂时触发保留地址拦截。仅临时映射已核实的 OpenRouter 和 Python 下载源。官方站点在接入实际工具时再按各自的真实 DNS 与 TLS 核对。代理排查
  • 公司内的真实本地模型地址按 v2 X4 留空。PR-D3 先用模拟的 OpenAI 兼容端点验收，真实地址到位后登记。
  • 容器部署当前用于本机回环，正式内网 HTTPS 入口依部署决定 D16 接入。新的隔离库执行迁移和开发账号初始化，L08 日常资料和真实 Cursor 核实由 Windows 工作台提供。
