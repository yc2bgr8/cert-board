## PR-25 对话接口、权限模式、插话与事件流

## 做了什么

- 项目成员可以查询项目对话、历史消息、进度和待处理事项。发起人可新建对话、发送、回答、停止及切换权限。写请求带 Cookie、来源和 CSRF 校验，重复请求号绑定原操作和内容。
- 新消息与运行同事务入队。插话进入持久缓冲，由同一 Pi 内核在当前工具批次结束后领取。问题回答关联原问题进入下一轮。过程批准仍通过自己的批准接口继续。
- 对话 SSE 按序号回补与续读，并持续验证浏览器会话。工具事件传定位和摘要，原始参数与资料正文保持在私有记录。个人通知流先以待处理快照覆盖批准、问题、阻塞和最终审核。
- 指定权限从下一次工具执行起生效。后续模型请求按现有模式重新取得工具目录。

## 没做什么

- 项目外对话可创建与列表展示，自动建立真实项目和工作区留后续业务工具接入。
- 对话附件及原件导入依赖 PR-17/19。正式聊天、批准、审核抽屉在 PR-26/27 实现。
- 真实模型保持日常账本冻结，当前使用隔离数据库与同一内核的剧本模型验收。

| `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm eval:agent` | 通过，330 项单元、30 项内核剧本 |

| `pnpm test:int` | 首轮 380 项中 379 项通过。历史不可清空断言按新外键修订，目标 7 项通过。最终全量与 CI 留待合并前核对 |
| 日常库 | 0014 迁移成功，重复新增 0。开发账号登录与后台启停通过 |
| `pnpm docs:html`、密钥扫描、CI 和独立复审 | 57 份离线 HTML。提交后完成扫描与复审 |

普通 `TRUNCATE conversation_message` 现在先被 0014 的插话回执外键以 `0A000` 拒绝。更新后的测试保留 `UPDATE`、`DELETE` 和 `TRUNCATE CASCADE` 的 `42501` 断言。停止请求已验证变参复用请求编号会返回 409，实际监听未收到新运行的取消通知。

最终复审发现待批准工具被公开投影误显示为已完成。补丁只识别新事件的受控等待标记，以及历史中严格匹配的待批回执，公开结果显示固定等待提示。保留过滤旧工具参数、正文及任意摘要的边界，新增两项回归。
