# PR-Q1 开发旗舰、稳定预览与真实走查

## 做了什么

- 开发期注册、维护 Agent 默认使用 `openai/gpt-6.2-astra-pro`。开发和测试保留逐次计量及步数限制，费用未知可续跑并留账。零保留端点、内部和保密资料的路由约束见决定记录。
- 核实默认加入 Cursor 的 Grok 4.7 和 OpenRouter 的 Claude Opus 5.5。沿用脱敏、权限复检和存档。核实运行取得限时执行权，在等待模型期间维持可用。
- 开发机增加稳定预览 28380 和走查环境 28280。持久数据、证据和日志分开。真实走查证据绑定提交，稳定预览等待进行中的对话结束再升级。
- 浏览器请求失败显示中文说明和错误编号。后端记录编号、路由、方法、状态和安全的诊断字段。对话可从走查链接直接打开。
- R09 和 M02 参照 SY-QP-15 A3、FDA 资料和空白记录模板。开发技能仍为草稿。

## 怎样体验

以 `zhangsan` 登录，密码在仓库根目录 `.env.local` 的 `DEV_ZHANGSAN_PASSWORD`。`pnpm walkthrough:real` 从干净的已提交工作树启动走查，运行真实浏览器、R09 初审与修改重提、M02、两条核实通道及错误编号检查。走查产物保存在 `.local/preview/evidence/`，其中 `result.json` 包含对话链接、模型和费用。使用 `pnpm preview:walkthrough` 可以再次打开走查对话。各服务日志在 `.local/preview/walkthrough/`。

正式走查通过后，`pnpm preview:lan` 启动或保持稳定预览。它使用本机入口 [稳定预览](http://127.0.0.1:28380)。稳定预览日志在 `.local/preview/lan/`。日常开发入口仍为 [开发工作台](http://127.0.0.1:28080)。

- `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm test:int`、`pnpm eval:agent` 及隔离浏览器验收。
