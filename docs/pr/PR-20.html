PR-20 Pi单一内核、运行执行权与持久过程

做了什么

  • 固定官方Pi 1.3.0，通过唯一适配层把模型请求交给现有网关；同一内核用于worker、剧本回归和真实Flash验收。
  • 领取与续期run租约；登记工具在原事务内、调用前和提交前验证owner/generation/数据库到期时间及中止信号。浏览器停止先独立发PostgreSQL通知，避免被正在执行的业务事务阻塞。
  • 私有对话消息、过程事件分别连续编号，只追加、幂等、按归属读取；run_event仍只有白名单元数据。模型及工具回执持久保存，提交审核或外发提案后立即停止同批后续工具。
  • pg-boss只接收runId，不存Agent正文、底层错误或模型凭据；取消自动重试，启动核对未结算旧请求，预算冻结后重新扫描交还运行。
  • 项目说明、单份开发Agent定义、历史和本次消息组成上下文。模型声称已提交不算成功，以真实审核工具回执为准；其余结束产生中途停止说明。

没做什么

  • RV-02完整11项验收尚未全部完成：本切片工具严格串行；并行只读优化延后。提案暂停已验证，批准后继续的内核路径按新变更在PR-21完成。没有把单元夹具中的读写当作完整业务工具接入。
  • 真实Flash仅验收多轮登记只读调用、连续事件与结束不重放；真实可撤销业务写入、结构化提交、提案批准继续及其余RV-02场景待PR-21主路径和PR-29评测。剧本及真实PG测试覆盖拒绝/停止/预算/审核链路。
  • Agent定义先使用仓库固定版本的开发草稿，生产拒绝；agent_definition_version发布管理、技能加载和正式评测留PR-24/29。按变更单B.1，已写的单份定义在PR-21拆为注册/维护两份。
  • 超长历史保守拒绝并提示新开对话，暂不做自动摘要；插话、提问恢复、计划工具、子Agent、唤醒分别在后续PR实现。
  • 没有沙箱执行工具，因此不存在宿主执行Agent代码的入口；实际无网络沙箱与隔离验收留PR-13/22。
  • 对话HTTP/SSE和正式界面尚未接入，浏览器主路径仍未完成；排期为C1、C2、C3、C4、21、25、26、27。

对应的需求和技术方案

  • 需求6.1、6.7、3.3；技术T02、4.4、4.7、4.27；变更单B.1允许本PR按原范围完成。

  • 审批仍只在浏览器闭包；后台/工具不能导入认证审批代码，工具目录无审批工具。

  • 未修改界面资源策略；沙箱、系统级宿主出网封锁尚未完成，不声称已经验证。草稿定义不对生产开放。
