PR-42 规则包与模板审核发布

范围

  • 系统维护人员在「设置 → 规则包与模板 → 查看审核列表 → 登记草稿」登记 YAML。已登录的注册人员可打开审核卡、核对版本和出处，然后通过或注明原因退回。技能继续使用已有的「技能版本」审核卡。
  • 草稿内容和已作出的决定均保留。登记时须明确密级，发布版本号须高于当前版本。通过决定与发布写入在一个事务内完成，记录实际审核人、会话、决定时刻和内容摘要。刷新后可查卡片状态。同一浏览器操作重试会沿用请求编号。
  • 规则需包含官方出处、条款和存档版本。标为待核对的规则以及没有单位的数值参数须先修订。正式环境的规则只读带有效人审记录的已发布版本，运行仍固定首次读取的版本。历史中缺审核记录的发布标记保留供追溯。开发环境可以读取已有明确标为开发种子的版本。
  • Agent 用 knowledge_get 的 kind=template 读取已审阅发布的公司模板，输出沿用对应模板密级。需要恢复旧正文时，维护人员在原审核卡点「以此版起草」，填写新的递增版本号后重新提交注册人员审阅。新运行会读取已发布的最高版本。
  • 复制已发布内容时保留版本号的填写空间。接近 32,000 个 UTF-8 字节时使用紧凑格式。若仍放不下，填写新版本号后由后台复制已发布的原内容，生成待审草稿。手工编辑超限时显示提示。

验收

  • 独立 Linux 虚拟机的定点集成覆盖管理员登记、普通成员审核、会话与 CSRF、旧草稿不生效、不可变发布历史、密级、幂等及发布冲突后的事务回滚。
  • 浏览器回归通过合成模板检查维护人员登记、普通成员审核、审核前无发布行和审核后记录实际决定人。界面沿用设计稿 15 的设置卡片与现有技能审核卡样式，在技能版本后增加一个可展开区。1440×900 浏览器截图
  • 真实模型与浏览器联合走查待可用的已授权网关。离线验证结果仅供开发，合并门禁仍需干净虚拟机全套正式验收和独立复审。

没做什么

  • 知识审核卡首版从设置打开。通知和「待我处理」入口后续接入。事实候选处理由 PR-57 覆盖。
  • 本次实现规则与普通文本模板的版本审阅。K05 的公司模板内容、文档渲染及 V1–V8 成品检查随 PR-47 处理。概念目录与查询模板按 PR-41 单独推进。
  • 只验证合成审阅素材，正式规则和模板由注册人员核对后发布。
