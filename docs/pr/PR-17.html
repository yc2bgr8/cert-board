PR-17 文档解析服务

对应需求 V1.0 §5.4，技术方案 v0.4 T09、§5，执行方案 PR-17。

做了什么

  • 增加隔离 docsvc。调用方传原件字节及 SHA-256，解析支持 PDF 文字层与 OCR、eSTAR 的 AES/XFA 与去重附件、docx、xlsx 和旧版 doc。PDF 页少于 40 个非空字符时采用 T1 的扫描页分流，记录每页方法和置信度。
  • POST /text 返回转换文本。GET /render 返回实际 PDF 原页，Word 和 Excel 先经隔离的 LibreOffice 转为 PDF。按哈希、类型和页码缓存。
  • Windows 开发使用 28082 固定回环中继。容器只连专用内部网段，无业务凭据。服务只接受固定类型和有界请求，每次执行一个转换，Office 使用独立临时配置。合成测试与 L08 原件对照在无网络容器中运行。

验收结果

  • pnpm test:py 运行原抓取服务测试和 7 项文档合成测试。覆盖 PDF 页、T1 字距兼容、真实离线 OCR、AES eSTAR、附件去重、Office 解析及图像渲染、请求哈希和上限。
  • pnpm dev:docsvc:up 启动实际服务。回环解析验证原件哈希，PNG 原页返回 200。容器无法直连本机业务数据库。
  • 用本机 L08 eSTAR 原件实测回环上传。原件哈希与 T1 一致，解析 1 页、去重提取 23 个附件，XFA 数据包与 T1 文件逐字节一致。
  • pnpm test:l08 对照 59 份资料和 664 页，逐份页数一致。117 页 OCR 的文字相似度均达到 0.98。两份旧版 Word 经 LibreOffice 转换后的文字均与 T1 一致，xlsx 由合成工作簿验收。
  • 535 页文字层在新版默认字距处理下有 169 页差异。诊断确认与 pypdf 的字距变化有关。保留 pypdf 7.1.1 的解析安全修复，仅复用 T1 的文字间距规则。271 页外层 PDF 的独立对照均逐字匹配，应用同一兼容规则的 L08 全量对照正在运行。pypdf 7.1.1 安全修复（外部链接）
  • 一次早期依赖诊断记录了字体描述元数据，后续运行已屏蔽相应依赖日志。对照结果使用资料编号、页码、方法和差异指标。

没做什么

  • 异步自动解析、资料权限入口和浏览器版面预览由后续入库与检索工作接入。本 PR 交付隔离服务接口和可复现对照。
  • 未引入真实模型或外发渠道，费用为 0 美元。
