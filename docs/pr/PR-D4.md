## 做了什么

- 注册和维护 Agent 都可以在三种对话权限下调用 `consult_external_model`。核实任务持久登记后由独立通道执行，结论经脱敏和原文重合检查后返回正在运行的 Agent。人工在群聊补充的意见随分类结果回传。
- 原对话显示进行中、已完成或暂不可用，点「查看群聊」查看发言。对话「停止」同时让关联群聊结束和整理。
- 审核卡发起的核实返回原对话，并在「依据」中显示结论、类别和出处。该对话下一次普通运行可读取最近一场已完成的核实，按项目原文判断是否修改或重新提交。审核决定仍由浏览器记录。
- 部门同事可从待审卡发起核实，群聊保留实际发起人，并用原对话的 Agent 主持。已处理的卡片保留可查询的核实历史。旧结果可以分页，原对话和审核卡沿用 SSE 接收更新，读取暂时失败时自动重试。
- Cursor 失联、默认模型未配置或整场没有可用模型回复时，Agent 可以继续使用项目资料，并收到保留不确定事项的提示。群聊最长等待十分钟，原对话保留继续查看的入口。
- 按原对话、运行与工作区中的最高资料级别拦截关联保密请求，派发前复查。外部发言回传为参考资料，原权限和审批来源仍由后端核验。

## 没做什么

- 原对话会立即显示审核发起的核实结果。结果作为下一次正常运行的参考，自动另起 Agent 运行未接入。原因和后续记录见 [D-039](../决定记录.md#d-039-关联核实的继续方式与资料边界)。
- 保密对话的独立改写和出网前的本地模型检查，在 PR-D3 提供本地端点后接入。当前关联保密对话保留本地记录并暂停派发。
- 出处链接和类别随群聊回传。官方来源的抓取、逐字核验及失败降级待 PR-D5。

## 开发机应用

应用迁移 `0023_verification_agent_links` 后，更新 API、Agent worker、核实 worker 和前端构建。沿用 D6 的 Cursor 隐私配置及浏览器入口 `http://127.0.0.1:28080`。

## 浏览器验收

- 独立测试端口使用 `CERT_E2E_PORT=28180`、`CERT_E2E_DIST=.local/d4-qa-dist`。通过 `pnpm --filter @cert-board/web exec vite build --outDir ../../.local/d4-qa-dist` 构建后运行 `pnpm test:e2e`，共通过 59 项检查。浏览器外部请求、CSP 违规、页面错误和未知用量均为 0。
- 剧本验证了自动核实返回人工补充、原对话和审核依据跳转、浏览器审批约束、停止联动，以及 Cursor 未登录时完成原文核对并在审核卡列出不确定事项。截图保留对应的对话状态与审核操作区。

`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm test:int`、`pnpm eval:agent` 和 `pnpm docs:html` 通过。包括 417 项单元、435 项集成、30 项剧本。
