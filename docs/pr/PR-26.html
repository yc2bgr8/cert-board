PR-26 界面外框与对话

做了什么

  • 登录后从项目栏查看 L08 510(k)、目标与历史。部门对话可以查看，发起人可以发送、插话、回答、停止和切换三种权限。
  • 对话按真实事件更新。工具过程默认折叠，计划、耗时和状态位于输入框上方。保存工作区改动和提交审核时在对话中显示状态。
  • 过程批准显示变更字段、原值与新值，或消息收件人和全文。允许、本对话中都允许、拒绝分别提交原批准请求。预览版本过期后先刷新，等待人再次确认。
  • 登录凭据随浏览器同源请求提交。外部链接带提示，原始 HTML 和外部图片过滤。本机浏览器验收使用独立测试库、真实 API 与 Pi 工作进程，用户、模型和内部队列使用测试渠道。
  • Zod 在浏览器加载共享模式前启用 jitless。生产构建继续使用原有严格 CSP。

与界面稿的差异

  • 正式入口先登录，?prototype=1 仍可查看 C2 静态稿。项目、对话与待处理事项来自后端。只有实际存在的维护项目会出现在维护列表。
  • 项目内 Agent 由项目类型确定，未关联项目时可选。对话模式仍默认请求批准。对非发起人显示共享对话历史，写入控制仅发起人可见。
  • 工具、计划、进度、问题和批准以数据库事件及接口回执显示。静态稿的附件、文件、资料和右侧最终审核入口等待对应接口接入。

没做什么

  • 上游字词级流式输出随模型网关接入。当前正文和过程按服务端增量事件更新。
  • 消息反馈及 message_feedback 写入、附件选择及上传、独立运行详情待后续。工作区改动目前显示保存状态，版本对比和证据页在 PR-27。
  • 项目外对话可保存，自动立项和工作区创建随后续业务工具接入。
  • 真实 Flash 的浏览器送审继续等用量核对。使用同一 Pi 内核和隔离库开展浏览器验收。
