# PR-19 整包导入

对应需求 V1.0 §5.7、技术方案 v0.4 §4.18、执行方案 PR-19。

## 做了什么

- 项目资料页支持 ZIP 上传、拖入 ZIP 和选择本机目录。目录在浏览器打包，上传用同源 Cookie 与 CSRF。支持查看导入状态、文件数量和分类，浏览器可修改分类。
- 后台通过租约展开和登记。检查嵌套层数、文件数、压缩比、总大小以及 NFC 后的重复、越界路径，全程不向文件系统展开。相同内容共用原件版本，所有来源路径留在报告中。
- 从 eSTAR 读取附件文件名及别名，登记子资料。原件经既有解析服务入库。已处理的包重复请求返回同一任务。
- 分类草稿依据组长申报清单章节和 T1 命名。未匹配项目保持「待确认」，人工改分类写入审计。

## 验收

- L08 本机原件打包后在独立测试库用认证 API 导入。外层 36 份、eSTAR 子资料 23 份、45 份唯一内容及 14 条重复路径，与 T1 核对表一致。59 条资料路径均完成解析，失败 0 条。重复提交返回同一任务，原始资料只留本机。
- [L08 核对表](../../fixtures/l08/intake_expected.json) 标为草稿，待注册人员确认。合成测试验证正常嵌套、大小门槛、路径规范化、等价重传、分类修改和逐页状态。
- [1440×900 浏览器验收](../evidence/pr-19-09-package-intake-1440x900.png) 验证上传、导入报告、分类和重复路径。界面沿用 09 的上传、统计和资料库结构，明细在可展开区域内。[09 设计稿](../变更单/界面设计稿/09-项目-资料与导入.html)

## 没做什么

- `doc_import` 的 Agent 工具登记、可撤销作用域和对话附件入口待后续。浏览器是本次整包登记入口。
- 模型分类及置信度回归待接入。22 条未匹配资料可人工分类，规则、分类和核对表等注册人员共同核对。
- 资料原页和原件下载仍待有授权的浏览器入口。

## 新增依赖与真实模型

- `yauzl` 3.4.0（MIT）和它的类型用于后端逐条查看 ZIP，`pend` 1.2.0（MIT）为其依赖。压缩内容走本机。[yauzl](https://github.com/thejoshwolfe/yauzl)
- `fflate` 0.8.3（MIT）用于浏览器把所选目录打包。两项依赖均未接入外部数据上报。真实模型费用为 0 美元。[fflate](https://github.com/101arrowz/fflate)
