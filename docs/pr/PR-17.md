# PR-17 文档解析服务

对应需求 V1.0 §5.4，技术方案 v0.4 T09、§5，执行方案 PR-17。

## 做了什么

- 增加隔离 `docsvc`。调用方传原件字节及 SHA-256，解析支持 PDF 文字层与 OCR、eSTAR 的 AES/XFA 与去重附件、docx、xlsx 和旧版 doc。PDF 页少于 40 个非空字符时采用 T1 的扫描页分流，记录每页方法和置信度。
- `POST /text` 返回对比用文本，保留 Word 正文块的顺序、内容重复的独立单元格和 Excel 公式。`GET /render` 用提交原件后签发的临时凭据读取 PNG，同时返回物理页总数。Word 和 Excel 先经隔离的 LibreOffice 转为 PDF，缓存按哈希、类型和页码索引。
- Windows 开发使用 28082 固定回环中继。容器只连专用内部网段，无业务凭据。服务只接受固定类型和有界请求，每次在可终止的独立进程中执行一个操作。合成测试与 L08 原件对照在无网络容器中运行。

## 验收结果

- `pnpm test:py` 运行 37 项抓取和 14 项文档合成测试。覆盖 T1 字距、离线 OCR、eSTAR 去重、原页临时凭据、缓存失效、进程超时恢复、表单和物理页数，以及 Word、Excel 的改动对比和 Office 正文丢失对照。
- `pnpm dev:docsvc:up` 启动实际服务。回环解析验证原件哈希，授权阅读的普通 PDF 可渲染 PNG。容器无法直连本机业务数据库。
- 用本机 L08 eSTAR 原件实测回环上传。原件哈希、首个文字页、XFA 数据包与 T1 一致，去重提取 23 个附件。复审后，服务对无法保真呈现的动态 XFA 返回专用错误。
- `pnpm test:l08` 通过。59 份资料的 664 页与 T1 页数一致，535 页 PDF 文字层逐字一致，117 页 OCR 均达到 0.98 相似度门槛。eSTAR 数据包逐字节一致，两份旧版 Word 和十份 docx 提取的文字一致。xlsx 由合成工作簿验收。
- 535 页文字层在新版默认字距处理下有 169 页差异。定位后仅复用 T1 的文字间距规则，保留 pypdf 7.1.1 的解析安全修复。全量对照的差异列表为空。[pypdf 7.1.1 安全修复](https://github.com/py-pdf/pypdf/releases/tag/7.1.1)
- 一次早期依赖诊断记录了字体描述元数据，已清理相关本地日志并屏蔽相应依赖输出。对照结果使用资料编号、页码、方法和差异指标。

## 没做什么

- 异步自动解析、资料权限入口和浏览器版面预览由后续入库与检索工作接入。本 PR 交付隔离服务接口和可复现对照。
- 动态 XFA 的可编辑表单版面核对继续使用原件以及解析出的 XML。真实模型费用为 0 美元。
