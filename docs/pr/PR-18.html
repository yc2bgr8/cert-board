PR-18 资料入库与检索工具

对应需求 V1.0 §5.4、§5.5，技术方案 v0.4 §4.1、§5、§7，执行方案 PR-18。

做了什么

  • 新增单原件登记和异步解析。已登录成员用同源 Cookie 和 CSRF 提交原件。原件保存到本地私有资料桶，采用 SHA-256 校验和去重。重复上传同一快照返回原版本。
  • 后台进程从 document_parse_task 领取版本，把原件发给固定隔离解析服务。成功时一次事务追加解析页、更新完成状态和追加审计。超时可重领，临时故障有重试，格式错误只保存安全错误码。
  • 资料页展示等待、解析中、已解析或失败，待解析时自动刷新，并继续提供上一可读版本的入口。检索使用最新已解析版本，摘要和原文带资料编号、版本和页码。低于 0.9 的 OCR 页带置信度提示。读取内部资料会保留会话的数据级别。

验收结果

  • 在独立测试库导入 L08 的 59 份、664 页 T1 基线。用 Cookie 与 CSRF 通过单原件接口提交 D005 PDF 和 D014 eSTAR，再由本机解析服务处理。D005 的 3 页可读，低置信页 1 页。D014 的外层页解析完成。中文「检验」命中 4 页，英文「predicate device」首批命中 10 页，均为内部资料。
  • 用合成资料在 1440×900 浏览器验证解析状态、已完成资料的原文入口及本站资源加载。运行截图 · 09 设计稿
  • 隔离部署实测 1,200,645 字节的合成 PDF 经反向代理登记，后台从内部解析服务得到一页原文。带会话上传返回 202，原文读取返回 200。未登录上传返回 401，其他接口仍拒绝相同大小的正文。
  • 相比设计稿，沿用现有资料行结构并应用其解析状态颜色。整包表格、报告与失败再导入随 PR-19 实现。

没做什么

  • 其余 L08 原件及 eSTAR 内嵌附件通过 PR-19 的整包入口重导。当前其余参考资料以已有 T1 快照参加中英文检索验收。
  • 文件选择器、目录及压缩包导入、分类和导入报告由 PR-19 接入。现有浏览器资料页提供解析状态与文本，原页和原件下载需要后续授权接线。

开发运行

运行 pnpm dev:up、pnpm dev:docsvc:up、pnpm db:migrate。在 .env.local 配置 CERT_DOCSVC_URL=http://127.0.0.1:28082，重新启动 API 及 pnpm dev:worker。容器部署使用 pnpm dev:isolated:web:up 的内部解析中继。

浏览器单原件入口为 POST /api/projects/:id/documents/original，正文是 application/octet-stream。查询字段为 name、format、可选的 sourceKey 和 dataLevel。该入口允许最多 96 MiB、同时最多两份上传。请求体连续空闲 30 秒或传输超过 12 分钟时终止。新版本返回 202，重复版本返回 200，未启用解析时返回 503。通过资料版本接口查看解析进度。

真实模型用量为 0 美元。没有新增软件依赖。
