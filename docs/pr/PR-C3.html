PR-C3 部门成员、三种权限模式与过程批准

做了什么

  • 登录身份改为部门成员，管理权限独立。迁移冻结旧角色绑定，停用非部门与旧开发账号并撤销其会话，保留历史用户、审计、报告和预算。项目复核人可空，不强制第二人复核。
  • 对话记录登记所属 Agent 与权限模式。旧执行模式迁为请求批准，原只读保留。成员可以读取同事的对话和项目资料，发消息、停止、过程批准和工作副本写入仍按发起人授权。
  • 工具按当前模式、成员、目标、动作级别和执行权判定。需要批准时保存当前参数、预览及版本，同一 Pi 内核暂停。只有对话发起人的浏览器会话可以作决定。会话授权限同一对话及工具版本。
  • 完全允许可以将内部消息排入仅本地测试的队列。队列绑定本项目联系人和有效开发成员，按北京时间日期限制同目标同收件人一次，处理前检查暂停、方向、权限、收件人版本及资料级别。暂停后恢复会取消旧排队，跨日积压失效。外部消息仍逐条生成提案。

没做什么

  • 精确执行已批调用、将拒绝理由交回 Agent、恢复运行在 PR-21 实现。当前接口记录决定，返回 executed:false，运行保留等待状态。
  • 请求批准模式下业务撤销若需要批准且没有有效的本对话授权，当前拒绝执行。工作副本等直接操作沿用原有撤销和版本检查。
  • 后续接入线程创建、运行中模式切换入口、批准卡和审核界面。历史独立判断与高风险门限由 C4 调整，D22 仍待质量负责人确认。
  • 内部队列目前通过受控本地测试处理器生成回执。常驻处理、真实渠道、非登录员工目录、工作日历和日摘要后续实现。
