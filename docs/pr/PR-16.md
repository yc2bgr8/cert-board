## PR

PR-16 提交审核与浏览器决定

## 做了什么

- 固定服务端R09开发草稿策略，重新运行V1/V3、最新工作区版本检查，至少两条去重完整引文均须有同对话成功doc_read回执。
- submit_for_review经登记可撤销写工具及同一事务建卡；重复call幂等，待审撤销标cancelled，不能撤销已经批准的卡。
- 审核卡不可变正文/hash/来源；浏览器GET、独立判断、通过/退回由真实Cookie、CSRF及来源验证进入私有路由闭包，并重验当前角色与引用权限。
- 高风险卡在本人hash绑定独立判断前不返回任何AI payload；他人的判断不可借用、原判断不可改写。
- 批准的快照、决定和卡片状态原子提交；重复批准只有一份快照，旧版本/目标方向/失效资料拒绝，失败不遗留部分冻结。
- 下一份报告的改动以真实浏览器已批准版本为基线，保留退回原因和审计。

- 修改后通过、追问、转交及目标继续事件留后续；本切片finalize只冻结报告，不产生真实外部提交。
- 技能正式发布与完整语义评测后续实现；R09明确草稿、dev-only，生产拒绝加载。
- Agent内核成功提交后的暂停、执行权fencing、实时对话和审核界面分别在PR-20/25/26/27接入；本PR为HTTP集成验证，不冒称浏览器主路径已完成。
