PR-D7 模拟外发结果与对账

做了什么

  • 生成持久的模拟邮件 Message-ID。明确成功或拒收直接判定。模拟断线只按 Message-ID 查询模拟服务的「已发送」，查不到或查不了时进入 reconcile。模拟服务负责自动存档，应用只查询。
  • 原发送编号最多尝试一次。结果未知和明确拒收在发起人的「待我处理」中显示。发起人可用浏览器确认未知结果已发出，或返回原对话重新提出。对账绑定版本、浏览器会话、发起人和操作编号。
  • 模拟企业微信以已有站内提醒为来源。超时或失败只重试一次并写入审计。站内提醒继续是正式记录。
  • 邮件有 Message-ID 时保留原编号。没有时按发件人、发送时间点和正文生成稳定的 SHA-256 来源编号，供 PR-54 转入时使用。

怎样体验

先在浏览器批准本地测试提案。批准接口回执中的 queueId 是测试队列编号。使用 pnpm outbound:simulate email <队列UUID> --simulate uncertain --sent-folder no_store 模拟超时且没有已发送副本，发起人可在「待我处理 → 外发结果」打开对账。将 no_store 换成 auto_store 可验证按编号查到并确认。缺省为 unavailable。

对一个已有站内提醒，使用 pnpm outbound:simulate wechat <提醒UUID> --simulate timeout --retry failure 验证两次失败后只留下审计。命令只接受开发或测试环境的回环数据库。

1440×900 浏览器按现有「待我处理」列表和外发提案右栏验证。合成邮件没有副本时出现待对账，编号和操作可见，发起人确认后从待办移除。重新打开原提案仍显示最终状态。浏览器截图

没做什么

  • 真实 SMTP、IMAP、企业微信和实际来信摄取分别留 PR-54、PR-50。IT 确认 SMTP 和 IMAP 行为之前，真实邮件断线和超时按结果未知处理。
  • PR-D8 独立处理技能退回提案。本 PR 未新增依赖或执行真实模型测试。
