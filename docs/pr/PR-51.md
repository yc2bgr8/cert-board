# PR-51 本机运维告警

## 使用

- 使用有管理权限的开发账号登录，打开「设置 → 维护页 → 告警」。页面展示当前活跃告警、最近检查时刻与过期状态。普通成员的浏览器会话无法读取告警接口。
- 后台每 30 秒检查既有本机服务与数据库记录。定时器仍使用原有扫描及心跳；告警检查超过三分钟未更新时，维护页提示检查后台进程。
- 模型网关只增加脱敏的失败分类，用于区分上游错误、超时和 OpenRouter 额度不足。原有返回值和计量流程照常。告警及日志留在本机。

## 阈值

- 服务探测失败、定时器超两小时未扫描、24 小时内唤醒失败、近一小时 OpenRouter 额度错误，以及已记录的最近一次备份失败，产生严重告警。
- 当前等待派发达到 20 条，或近一小时在至少 5 条样本时队列失败率及网关失败率达到 20%、网关超时率达到 10%，产生警告。
- 费用按既有月度告警比例、当月已结算金额产生警告。后端工作目录所在磁盘剩余少于 5 GiB 或 10% 时提示。无法取得的信号不用于声明已有告警恢复。

## 验收

- `pnpm exec vitest run apps/backend/src/ops/rules.test.ts apps/backend/src/worker.test.ts apps/backend/src/modelgw/transport.test.ts` 检查所有告警规则和后台生命周期。
- `node scripts/test-integration.mjs apps/backend/src/ops/service.int.test.ts apps/backend/src/ops/guards.int.test.ts apps/backend/src/modelgw/service.int.test.ts` 检查实际数据库、管理员隔离、故障登记与恢复、后端用量分类及原计量。
- `pnpm test:e2e` 从浏览器维护页验证告警。[1440×900 界面证据](../evidence/pr51-16-ops-alerts-1440x900.png)
- 开发验收已通过 16 项单测、34 项专项集成和 Chromium 回归。模拟 402 仍按既有账本记为待核，维护页仅显示告警分类。浏览器外部请求、页面错误及模型费用均为零。
