# PR-28 目标等待、唤醒与核实续跑

## 做了什么

- 对话调用 `consult_external_model` 后保存核实等待并释放队列处理进程。同一结论只恢复一次原运行，续用原预算并把结论交给 Agent。审核卡的「让Agent核实」以原对话的新运行收到工具回执。
- 对话中的「停止」取消核实等待并联动停止该次群聊。后续到达的结论不会重新派发已取消的等待。重启后继续扫描仍有效的等待。
- 增加 `wait_register`、资料版本到达、定时和人工确认唤醒。新对话属于项目目标负责人，根据项目类型选择 Agent。目标接管和交还只接受授权的浏览器请求，记录方向版本和审计。
- 审核卡的人工决定在原对话续跑。审核本身继续通过浏览器会话与 CSRF 校验。对话文字与 Agent 工具不能作出人工审核决定。
- 按 v5 增加核实截止及整理宽限、审计和迟到提醒。等待中继续收消息。续跑检查成员、对话、目标接管与方向，结果不可继续时进入负责人的「待我处理」，必要时转管理员。新开的唤醒对话读取登记的下一步打算。

## 没做什么

- 正式目标接管、确认和交还界面。现有授权浏览器接口可用。交还的信息以目标方向记录提供给 Agent。
- 普通目标唤醒的正式通知流，以及派发失败时的退避和告警。核实迟到或权限受阻有独立的待处理通知。已开始的模型执行仍使用现有账本及中断处理。
- 维护目标和离线唤醒直至生成审核卡的完整自动验收。离线新建注册对话、接管阻止唤醒和交还恢复有专项覆盖。浏览器主路径单独验证实际审核卡、核实和继续运行。
- 真实外发在 PR-50、PR-54 接入前按 D-050 实现持久防重复编号及失败对账。

## 验收

- 使用一个 PgBoss 工作槽，核实挂起期间另一个对话正常完成。重新启动队列后，推进持久等待的测试时间超过 15 分钟，模拟通道返回结论。并行扫描和重复入队仅恢复原运行一次。
- 1440×900 浏览器验收覆盖审核卡发起核实、收到工具回执、正式通过后续跑、对话停止联动、Cursor 未登录时的不确定事项，以及 CSP 和零浏览器外网请求。
- 需求 V1.0 第 2.5、3.1、3.3 节，技术方案 v0.4 第 4.3 节，[v5 第 1.1 节和附录 B.2](../变更单/需求变更单_2026-11-20_核实续跑与外发结果.md)，以及 [D-050、D-053、D-054](../决定记录.md)。

真实模型测试与新增依赖均为无。
