# PR-47 K05 文档模板草稿和逐段出处

## 当前切片

- 按 v7 K05 先提供一份基于公开 FDA 参考的通用 510(k) Cover Letter 草稿。模板在 `knowledge/k05/us-510k-cover-letter.yaml`，状态为草稿，待注册人员确认。
- 草稿按申请人、器械和申报缘由组织。正文保留待核位置。签署与日期由提交人审阅后填写。eSTAR 的 Cover Letter 部分作为草稿用途参考。[FDA 附件结构](https://www.fda.gov/media/152429/download) · [FDA Cover Letter 建议](https://www.fda.gov/medical-devices/premarket-notification-510k/content-510k) · [FDA 格式提示](https://www.fda.gov/medical-devices/premarket-notification-510k/510k-format-tips)
- 注册 Agent 的 `k05_cover_letter_draft` 工具在交付子目录生成 Markdown 和逐段来源表。只有引文实际包含完整字段行，且所引同版资料页中没有冲突值，才填入草稿。资料库版本和页码、本对话 `doc_read` 回执以及资料级别一并检查。缺项和含义不明的字段保留待核位。从标明合成的资料生成时，草稿也带合成标记。
- K05 信函与来源表同时写入工作副本，可用既有工具撤销。保存后送审时，后端核验两份文件与同一次生成回执的路径及哈希，拒绝另存到未登记路径的原产物，并确认送审附有采用的原文和可用来源。其他结构化检查及浏览器审批照常执行。
- 合成样稿通过既有隔离沙箱编排成 Word 和 PDF 预览。Markdown、Word 和 PDF 均标明使用合成数据，三种格式的哈希记录在随附来源表。

## 开发验收

- 定点测试覆盖合成 Cover Letter、逐段出处、否定或冲突字样、缺项、未签署占位、项目资料级别和送审时的文件完整性。
- 隔离机开发集成已验证只读拒写、草稿撤销、另存或改写拒审、补齐原文后建立待审核卡。集成测试按工具边界的脱敏错误码和修正提示验收。
- `pnpm test:k05` 在本机 `.local/` 写入合成草稿和 JSON 来源表，每次建立新的目录，供开发走查。
- `pnpm dev:sandbox:up` 后运行 `pnpm test:k05:word` 可生成合成 Word 草稿和 PDF 预览。
- 真实模型及最新版提交的正式合并流程继续按独立虚拟机约定执行。

## 没做什么

- 正式模板登记、人审发布随后接入 PR-42 的发布存储。其他通用模板、公司专用格式和正式交付入口尚待继续。
- 通用市场规则包的文件命名联动、适用的 V2、V4、V5、V8 整体检查及 Word 交付接入工作副本，仍需后续验收。
