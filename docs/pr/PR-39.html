PR-39 切片部署和备份恢复

使用现有隔离部署 pnpm dev:isolated:up。网页只在回环端口监听，数据库和 MinIO 仍在 Compose 内部网段。备份不需要网络或模型凭据。

冷备份

在维护窗口运行 pnpm dev:isolated:stop，停止隔离工作台、后台、数据库与 MinIO，保留已停的源容器和数据卷。备份过程中保持这些服务停止。日常工作台和稳定预览使用各自的项目与卷。

运行 pnpm backup:save。脚本校验项目、卷标识、数据卷无人使用、PostgreSQL 已正常停库，然后只读复制两个命名卷。输出位于 .local/backups/<备份编号>/，包含两个归档与 SHA-256、大小和镜像编号清单。成功前保留为隐藏的临时目录。归档含业务资料与数据库认证状态，应按源资料权限保存。Windows 使用仅当前维护账号可访问的目录，Linux 脚本校验目录的私有权限。不要提交或转发归档。

恢复演练

在只存放受信任备份的独立环境运行 pnpm backup:restore <备份编号>。先校验整个归档与原镜像版本，再生成一个 cert-board-restore-… 项目并创建空卷。验证时使用同一 Compose 文件、恢复项目名和源环境对应的凭据启动 PostgreSQL 与 MinIO。恢复命令只填充新卷，源部署仍由日常部署流程管理。

pnpm test:backup 只在干净的独立 Linux KVM 上运行。演练使用合成资料和临时凭据，核对带数据的卷、所有应用表行数和对象文件 SHA-256，测试运行中的源与损坏的备份拒绝操作。
