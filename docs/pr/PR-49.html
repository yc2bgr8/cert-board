PR-49 人工改稿回收与反馈

如何体验

  • 在 Agent 消息或审核卡上点「有用」「没用」。「没用」可以填写原因。刷新后可查看自己的最近选择；同一请求重试会返回原回执。
  • 从项目「文件」的「上传修改稿」或审核卡的「改动 → 人工修改稿」上传完整文件。系统找到对应的 Agent 审核原稿，另存为人工版本，并分页显示所增删的段落。可以继续上传同一审核卡里尚未改过的其他文件。已被改动的同路径文件需要重新核对。
  • 上传前显示对照的文件和 Agent 原稿版本。在审核卡切换对照文件后，需要重新选择本机修改稿。保存成功显示实际工作区版本，可直接打开本次修改的段落对比。
  • 支持在 Word 或 WPS 中编辑后手工上传的 .docx，以及 UTF-8 Markdown 和纯文本。.docx 由本机解析服务按正文和表格顺序抽取段落。原稿与修改稿的文件字节随工作区版本保存，段落摘要用于核对文本变化。
  • 上传断开时，可以点「确认上次上传」。会话内沿用原请求和工作区版本，取回已保存的回执；浏览器把文件选择框清空后可为另一个路径重选本地文件。
  • 文件只在浏览器和本机工作区存储间传递。旧稿、原审核状态和已批准快照保留。人工版本与审核卡、原稿和实际技能版本一起记录。

验收

  • pnpm exec vitest run apps/backend/src/workspace/paragraph-diff.test.ts 覆盖段落位置、换行差异和显示上限。
  • node scripts/test-integration.mjs apps/backend/src/conversations/human-feedback.int.test.ts apps/backend/src/workspace/human-revision.int.test.ts apps/backend/src/workspace/routes.int.test.ts 检查会话和 CSRF、跨对话目标拒绝、反馈版本、重复请求、人工身份、同路径覆盖保护及多文件保留。
  • pnpm test:e2e 在合成数据上通过 Chromium 核对浏览器反馈、上传新版本和段落明细。界面证据
  • 开发验收已通过 2 项段落单测及 7 项专项集成，Chromium 回归检查两类反馈、改稿与既有文件对比，非本站请求、页面错误和模型费用均为零。
  • 新增回归检查原稿版本、切换文件后清除旧的本机稿，以及由保存回执打开实际段落差异。断流后取回同一次上传的检查继续保留。
  • 正式真实模型走查、最终提交的全套独立验收与独立复审列为合并门禁。

没做什么

  • WPS 自动同步按 D03 延后。段落摘要中的截断部分可通过工作区版本核对，版面上的变化通过原文件预览或下载核对。
  • 反馈和差异作为改进输入。自动生成改进提案、评测回归与技能更新由 PR-58 处理。
