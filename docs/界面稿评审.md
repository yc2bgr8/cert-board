# 界面稿评审（PR-C2）

状态：**待注册人员确认**。设计方向以已确认的[2026-11-18变更单附录A](变更单/需求变更单_2026-11-18.md)为准；按Lan授权先完成开发验收并继续后续PR，不伪造对具体界面的人工确认。

## 布局与用语

- 白底、黑灰正文、浅灰左栏、细分隔线；不使用深色导航、渐变、阴影卡片、眉题或装饰性编号。强调色用于主要操作、焦点和待处理事项。
- 左栏约248px，可收起，含新对话、搜索、待我处理、注册项目、维护事项和各自对话；人名及设置在底部。
- 对话列最大约760px。顶部一行项目及对话信息，配对话、文件、资料切换；右栏约520px，仅审核、证据、改动需要时打开。
- 使用15px/1.75正文、14px控件、13px次要信息、18px项目标题；系统字体，不加载网络字体。注意色只用于图标/边框，文字保持可读对比度，见D-022。
- 人的消息靠右浅灰底，Agent消息直接排版；工具过程默认折叠。计划和运行状态在输入框上方，每完成一步在对话中汇报。
- 新对话可选注册Agent或维护Agent，项目内固定所属Agent；权限模式默认请求批准，可选择只读或完全允许，并显示说明。
- 过程批准提供允许、本对话中都允许、拒绝；最终审核按结论、需要你做什么、过程中作出的判断、改动、依据、自检、不确定事项、操作八部分展示。
- 主要审核操作为通过、退回修改；其余操作收在更多操作中。引用可打开对应原文，修改可打开文本对比；显示工作区版本。

## 界面稿边界与三条路径

所有资料、K号、联系人和执行回执均为虚构演示。K123456/K123465不代表真实L08资料，也不能据此认定实际对比器械编号。演示不调用后端、不调用模型、不写业务数据库、不发真实消息。按附录A.8，开发说明仅放在设置里。

原页是按虚构文本排版的本地HTML纸页，用于验证与解析原文并排对照的交互，不是实际PDF解析产物。

1. 注册项目：在L08 510(k)对话中发送K号写法检查，看到计划与进度；在关键判断批准卡上允许后，打开八部分审核并通过。
2. 维护事项：进入L08 年度注册，选择完全允许后核查；对话展示更新提醒和给内部同事催办的本地演示回执，再提交审核。
3. 待我处理：可以保留注册对话的批准请求，再运行维护核查，列表分别提供批准请求与待审核结果入口。

审核动作在本PR中只是浏览器状态演示。真实身份、权限模式、批准恢复、最终审核及冻结分别由C3/C4/21/25/26/27接入并验收。

## 打开方法

开发方式：在仓库执行 `pnpm dev:web`，打开 `http://127.0.0.1:28080`。构建验收方式：`pnpm build` 后运行 `pnpm preview`，使用相同地址；两者不能同时占用28080。

本PR静态界面不需要登录。正式开发账号及密码变量以最终晨报为准，此处不能视作登录功能已经接入。
