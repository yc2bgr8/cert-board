## 两个工作日的体验

1. 在 L08 510(k) 项目进入注册对话，选择「请求批准」，输入「检查L08申报资料中对比器械K号的写法」。展开读取资料和工具过程，点开引用核对原页。进入审核卡检查差异、过程判断和待确认事项，再按实际情况批准或退回。退回时给出具体原文和需改位置，检查重提是否保留未改内容。
2. 进入维护项目检查证照和到期提醒。随机对照几条原表、型号、证照和提醒对象，记录有来源、缺失及边界问题。使用已启用的台账问答，再问一项未启用的口径，核对系统是否告知无法回答。
3. 由注册人员代销售提出一条 S01 请求。检查草稿的事实、附件用途、版本与出处，再核对准备耗时。对照 CPAP 注册立项、分类、路径和证据计划，将 Agent 的候选与注册人员独立判断一起记下。
4. 每天记录所处版本、是否实际使用、完成用时、问题及反馈。报告只写匿名类别、编号和判断结果，原始工作材料与本机证据留在授权位置。接触到严重问题时保留证据、停止相关试用并把具体情形交负责人员核查。

软件验证完成前，AI 的结果只作参考。正式记录、签字、对外提交与付款由人按现行流程完成和核对。依据 v7 D20、需求 NF09 和执行方案 6.2。[已确认决定](变更单/需求变更单_2026-11-20_待确认事项的决定.md)

## 指标与反馈

从同一版本收集运行、浏览器、主数据抽查、安全检查和人员记录的脱敏摘要。开发测量用 `pnpm measure:v1 <脱敏测量JSON>`，正式验收记录放入独立虚拟机报告和评审记录。两天体验后收集评审意见，按需求 8.6、8.7 汇总问题及待核项。[指标记录](pr/PR-52.md)
