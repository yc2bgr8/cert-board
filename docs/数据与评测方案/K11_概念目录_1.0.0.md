# K11 认证台账概念目录 1.0.0

草稿，待注册人员确认。查询模板在开发和测试环境可用。正式环境须确认目录和查询口径后启用。

| 概念 | 表和字段 | 定义、单位与来源 |
|---|---|---|
| 产品、型号、品牌 | `product.id/code/name`、`model.id/product_id/code/status` | 型号代码连接研发和认证，从受控产品型号台账导入。品牌字段和同型号多品牌的口径待 PR-43 对齐。 |
| 型号×市场授权 | `market_authorization.model_id/market/status/credential_id` | 型号在 US 或 CA 的登记状态为未申请、申请中、可售、已列名或停用。可售和已列名同时核对关联证照的型号、市场及现时有效性。缺记录时状态未知。 |
| 证照与到期 | `credential.project_id/holder_entity_id/market/credential_number/effective_date/expiry_date/expiry_kind/status` | 来源为经核对的证照或原台账。日期与剩余日数使用所属项目法域。已知长期有效和到期未知分别登记。 |
| 企业注册与列名、美国代理人、GUDID | `credential.credential_type/credential_number/source` 与 M02 的公开证据 | 依据官方核查和原台账。来源冲突时交注册人员核实。首版的台账查询采用已核对的结构化台账，公开实时取证由 M02 处理。 |
| 节点与逾期 | `cert_milestone.project_id/planned_date/completed_date` | 日期来自经核对的项目计划。按项目法域日历日，计划日在今天以前、尚无完成日的节点为逾期。 |
| 待我审核 | `review_card.project_id/conversation_id/status/created_at` | 与「待我处理」的最终审核一致。有效部门成员可处理范围内的待审卡，创建时间为 UTC 时间点。 |

| 模板 | 参数 | 可回答性 |
|---|---|---|
| `credentials_expiring` | `days` 为 0 至 7305 的整数 | 范围内已生效的有效定期证照，含今天和第 N 天。有效证照的到期未知会形成缺口。 |
| `model_market_status` | `modelCode` 为精确型号代码 | 按范围返回已登记的市场状态。指定项目覆盖项目法域，部门范围查看 US 和 CA。缺状态、有效关联证照或型号时分别注明相应缺口。 |
| `market_sellable_models` | `market` 为 US 或 CA | 只列启用型号中明确已登记可售、具备现时有效关联证照的记录。列名状态不纳入可售。 |
| `overdue_milestones` | 无额外参数 | 按项目法域日期计算，给出逾期日数。 |
| `pending_my_reviews` | 无额外参数 | 直接以待审系统表为准。超过上限时提示截断。 |

所有模板默认查询当前项目。用户明确要求部门台账时可查部门范围。台账导入或核对后由受控流程记载 `cert_query_coverage`，按项目、数据集和核验时间区分已核对空台账与未核对数据。完整结果可以是零行。能返回已知记录但有缺口时标为「部分」，缺口使本次没有可用记录时标为「无法回答」。每行返回记录编号和版本。可售和已列名回执同时返回依据证照的编号和版本。

单次最多返回 100 行。执行事件记录模板、目录版本、范围类型、查询时刻、可回答性、缺口和截断标记。模板与版本可查回本页中的单位和口径。详细行及项目编号留在工具回执。 [技术方案 4.9](../技术方案/AI原生器械认证板块_技术方案_v0.4.md#49-业务语义层)
