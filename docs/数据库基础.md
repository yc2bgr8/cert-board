# 数据库基础（PR-02）

实现依据技术方案4.16、4.22、第6章，六张表均存带时区的时间点。

| 表 | 用途 | 关键约束 |
|---|---|---|
| app_user | 账号、状态、密码哈希 | 仅Argon2id；用户名唯一；开发账号有独立标记 |
| role_binding | 角色和对象范围 | global/project/own范围；空scope也参与唯一约束 |
| web_session | 浏览器会话 | 只存会话token与CSRF的哈希；到期与撤销时间 |
| audit_log | 追加审计 | 仅动作、对象、操作者和前后哈希；数据库拒绝更新、删除、清空 |
| legal_entity | 法律主体 | 名称、地址、国家和主体类型 |
| entity_role | 主体在市场中的角色 | 引用主体、市场、角色、来源；有效期可空，不虚构日期 |

业务表具有正整数版本和创建/更新时间。领域服务后续实现乐观版本更新；本PR不声称已实现业务增改接口。

`cert_board_reader` 无登录能力、无写入权，只能读取法律主体和主体角色；不能读取账号、会话和审计。后续新增业务表逐表授予读取权限，不设置全库SELECT默认权限。

迁移由Drizzle生成并保留SQL，补充数据库级约束后审阅。`cert_schema_migration` 保存执行文件名和SHA-256；迁移按编号执行、加会话级互斥锁、每个版本一个事务。历史文件被修改或删除时拒绝继续，失败版本的DDL和账本一起回滚。

开发种子只在development/test可用，重复运行不重置密码、状态或权限；同名账号若没有开发标记则整笔拒绝。角色为RA/RB/GM/SALES/TECH，销售只分配own范围，其余开发角色分配global范围。生产运行禁止使用这些种子，后续登录模块也必须拒绝生产环境开发账号。

集成测试建立本次独有的随机测试库，使用测试配置并在结束后删除；不清空日常库，不改动其他项目数据库。
