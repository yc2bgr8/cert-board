# 主表与数据字段

> 与数据库表一一对应（迁移 `db/migrations/0026` 起）。“必填”列为 是 的字段在页面和数据库两层校验。日期都是北京时间的日历日。
> 人员字段都指向平台账号（`app_user`），不是角色名；同一个人可以兼注册A、注册B 以外的角色。

## 一、认证线成员 `cert_member`

| 字段 | 必填 | 说明 |
|---|---|---|
| 账号 | 是 | 平台账号 |
| 认证线角色 | 是 | `RA` 注册A、`RB` 注册B、`GM` 总经理（决策项）、`TECH` 技术人员（维护模板）；一人可兼多个 |

只有注册A、注册B 能新建和修改台账；节点、派工项、整改项的责任人可以把自己负责的事项标为完成。

## 二、主表三：产品—型号—市场—证书

### 产品 `product`

| 字段 | 必填 | 说明 |
|---|---|---|
| 产品代码 | 是 | 唯一，大写字母和数字，例如 `CPAP` |
| 名称 | 是 | 例如“JoyBreath CPAP 主机” |
| 说明 | 否 | |

### 型号 `model`

| 字段 | 必填 | 说明 |
|---|---|---|
| 型号 | 是 | 唯一，例如 `JB-C1`；认证线和研发线的连接键 |
| 所属产品 | 是 | |
| UDI-DI | 否 | GS1 格式，未分配时留空并在页面显示“待分配” |
| UPC | 否 | 12 位数字，申请中时留空 |
| 包装层级 | 否 | 例如“单机 / 内盒 / 外箱” |
| 关联研发项目 | 否 | 研发项目代码，例如 `JBR` |
| 状态 | 是 | 在用、停产 |
| 来源 | 是 | 导入的原台账文件名和行号，或“平台录入” |

### 型号 × 市场 `market_authorization`

| 字段 | 必填 | 说明 |
|---|---|---|
| 型号 | 是 | |
| 市场 | 是 | `US` 美国、`CA` 加拿大（以后按需增加） |
| 状态 | 是 | 未申请、申请中、可售、已列名、停用 |
| 依据证照 | 否 | 可售、已列名时必填（例如 510(k) K 号、MDL） |
| 申请中的认证项目 | 否 | 申请中时填写 |
| 备注 | 否 | |

**校验：** 同一型号同一市场只有一条记录；“可售”“已列名”必须关联证照。

## 三、主表二：证照到期表 `credential`

| 字段 | 必填 | 说明 |
|---|---|---|
| 证照号 | 是 | 平台编号 `CR01` 起，自动生成 |
| 类型 | 是 | 510(k)、加拿大 MDL、MDEL、MDSAP 证书、FDA 企业注册、器械列名、GUDID、美国代理人协议、年费、加拿大进口商协议、代理合同、其他 |
| 编号 | 是 | 官方编号或合同号；测试环境只用虚构编号 |
| 持证主体 | 是 | 公司名称或代理人 |
| 关联型号 | 否 | 企业级证照（企业注册、MDSAP 证书等）不填 |
| 市场 | 否 | |
| 生效日 | 否 | |
| 到期日 | 否 | 长期有效（例如 510(k)）不填；填了就进入 90/60/30/当天提醒 |
| 费用、币种 | 否 | |
| 负责人 | 是 | 提醒发给此人 |
| 来源 | 是 | 原台账或文件名 |
| 证书扫描件 | 否 | 存文件存储，路径前缀 `cert/` |
| 状态 | 是 | 有效、已失效、已注销 |

## 四、主表一：认证项目进度表

### 认证项目 `cert_project`

| 字段 | 必填 | 说明 |
|---|---|---|
| 项目号 | 是 | 平台编号 `C01` 起，自动生成 |
| 名称 | 是 | 例如“JoyBreath CPAP 510(k)” |
| 市场 | 是 | 美国、加拿大、美加（MDSAP） |
| 路径 | 是 | 510(k) Traditional / Special / Abbreviated、De Novo、MDL Class II–IV、MDSAP 初审 / 监督审核 / 再认证、年度更新、其他 |
| 型号 | 否 | MDSAP 等体系类项目不填 |
| 关联研发项目 | 否 | |
| 主责、复核 | 是 | 两名不同的注册人员 |
| 目标日期 | 是 | |
| 状态 | 是 | 准备中、已提交、审评中、发补中、已批准、未通过、已结项、已取消 |
| 申报号、提交日、受理日、下一动作 | 否 | 提交后填写（P10） |

### 节点 `cert_milestone`

| 字段 | 必填 | 说明 |
|---|---|---|
| 认证项目 | 是 | |
| 类型 | 是 | 测试、样品、付款、报告草稿、报告终稿、提交、受理、发补、回复、批准、续费、整改、审核、其他 |
| 内容 | 是 | 例如“电气安全与 EMC 送测样机寄出” |
| 计划日期 | 是 | |
| 完成日期 | 否 | 填写后节点完成，不再提醒 |
| 责任人 | 是 | |
| 来源 | 否 | |

## 五、定时器 `timer`

| 字段 | 说明 |
|---|---|
| 对象 | 证照、节点、派工项、整改项、发补问题项等 |
| 规则 | `D-90`、`D-60`、`D-30`、`D0`（证照）；`D-7`、`D-1`（节点、派工、整改）；`OVERDUE`（逾期当天） |
| 触发日、到期日 | 按北京时间的日历日 |
| 负责人 | 对象的负责人 |
| 状态 | 待触发、已提醒、已确认、已作废（日期改动后旧提醒作废） |
| 确认人、确认时间 | |

## 六、其他台账

| 表 | 主要字段 |
|---|---|
| 机构 `vendor` | 名称、类型（实验室、CRO、当地代理、顾问）、能力、资质、联系人、历史表现（1–5 分）、在用 |
| 询价 `vendor_quote` | 认证项目、机构、测试项、报价、币种、周期（天）、报价日、是否选中 |
| 测试项 `cert_test_item` | 认证项目、名称、标准、机构、状态（计划、已送样、测试中、草稿、终稿） |
| 申报清单项 `submission_item` | 认证项目、章节、内容、关联平台文档或上传文件、负责人、截止日、状态（缺、编写中、已有、不适用） |
| 一致性检查 `submission_check` / 差异 `submission_diff` | 检查时间、缺件数、差异数；每条差异的字段、两处来源和取值、确认结论 |
| 申报快照 `submission_snapshot` | 认证项目、序号、类型（演练、正式提交）、文件清单（版本、sha256）、清单哈希、生成人和时间；不可修改 |
| 发补 `deficiency` / 问题项 `deficiency_item` | 来函日期、截止日、机构、状态；问题、原文引用、责任人、截止日、底稿、证据引用、状态、交叉检查人 |
| 法规源 `reg_source` / 法规更新 `reg_update` | 源名称、地址、开关、最近成功时间、连续失败次数；标题、链接、发布日、摘要、影响型号候选、结论、确认人 |
| 同类检索 `predicate_search` | 产品代码、关键词、结果（K 号、器械名、申请人、决定日、摘要链接）、注册A 结论 |
| 请求 `report_request` | 类型（合规报告、UPC、FDA 企业注册与列名、GUDID、MDL、MDEL）、请求人、型号、用途、状态、底稿文件、审核与交叉检查人 |
| 审核 `qms_audit` / 清单项 `qms_audit_item` / 发现项 `audit_finding` | 审核类型、日期、审核方、范围；条款、证据、状态；等级、描述、整改负责人、截止日、状态 |
| 检索分块 `doc_chunk` | 来源对象与版本、分块序号、文本、语言、向量、向量模型名与版本 |
