# 轻量试用结论与 Agent 决策（PR-65）

> 依据：技术实施方案第十三节“AI 实现方式”、执行计划第十节 PR-65。
> 状态：**暂定决定，待技术负责人和注册A 确认。** L-1、L-2 内网轻量试用要到 2027-01 底才完成，所以本文先按现有证据给出暂定决定，并写明什么条件下改。L-2 结论出来后补齐第 2 节，再请两人签字。

## 1. 要决定的事

发补应答底稿（④，PR-67）和同类产品检索（②，PR-64）要不要从“单次调用 + 检索”改为 Agent 循环（多步检索、自己决定下一步查什么），即在阶段 1 提前引入 pi-agent-core。

## 2. 依据

| 依据 | 现状（2026-11-13） | 结论 |
|---|---|---|
| L-1 申报一致性检查轻量试用（内网） | 进行中；检查项和样例已作为 PR-57 的需求 | 与本决定无直接关系（③ 只做抽取和程序比对，不需要多步） |
| L-2 发补拆项与应答轻量试用（内网） | 进行中，2027-01 底完成 | **待补：** 单次检索取到的历史应答和证据是否够用；需要追问几次才凑齐 |
| PR-64 同类产品检索（云端） | 已上线（#72）：一次查询同时取 openFDA 产品分类和 510(k)，模型只整理候选，每条回到官方记录 | 单次调用够用。注册A 需要换关键词时手动再查一次，成本低，不需要模型自己多步查询 |
| PR-55 混合检索 | 已上线：trgm + pgvector，RRF 融合；embed 不可用时退回字词匹配 | 单次检索的召回质量可以先用评测集量化（PR-71） |

## 3. 暂定决定

1. **阶段 1 不引入 Agent 循环。** ② 和 ④ 都按“单次调用 + 检索”实现，pi-agent-core 仍推迟到阶段 3。
2. **PR-67 的做法：** 每个问题项先用混合检索取历史应答和证据（按问题原文和关键词各取一次，结果合并，最多 8 段），模型只根据这些段落起草。引用必须逐字回到检索到的原文，否则整段丢弃。注册A 不满意时，可以手动补充检索词重新生成。
3. **预留接口：** 底稿生成写成“检索 → 起草 → 校验引用”三步函数，检索步骤可替换。以后改用 Agent 循环时只换检索步骤，工具仍然只开放平台内检索和 openFDA 查询，校验和人工确认不变。

## 4. 什么时候改

出现以下任一情况时，在 L-2 结论中写明，并重新决定（另开文档 PR）：

- L-2 中超过 30% 的问题项需要追问两次以上，才能凑齐应答所需的历史应答和证据；
- PR-71 评测中，④ 底稿的引用召回率低于 70%（以注册A 标注的应答依据为准），而且加长检索词也没有明显改善；
- 注册A 反馈 ② 的同类清单需要反复换关键词、手动检索明显耗时（每个项目超过 30 分钟）。

## 5. 对其他 PR 的影响

- PR-66、PR-67：按第 3 节实现，不依赖 pi-agent-core。
- PR-71：评测集加入 ④ 的引用召回率与 ② 的“回到官方记录”比例，作为第 4 节判断依据。
- 技术实施方案第十三节“AI 实现方式”不用改。
