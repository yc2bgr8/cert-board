需求变更单（2026-11-18，二）：本地主模型、外部模型协作与权限放宽

文档版本：2

编制日期：2026年11月18日

文档状态：已确认（Lan）。版本1于2026-11-18经Lan合并进 main；版本2写入第3节待确认事项的决定，并增加附录C「连续开发授权」。

适用对象：Lan；在开发机上开发的Codex；注册人员

2026-11-18管理层与Lan讨论后，对模型策略、Agent的权限和联网方式作出调整。方向是：Agent在公司内部放开干活，控制集中在「数据离开公司」和「对外的事」两个边界上；主力模型用公司本地部署的模型，外部顶级模型作为Agent可自由调用的工具，用来补足本地模型的能力。

本变更单优先于以下文档中与之冲突的内容：《需求文档V1.0》《总体方案v0.5》《技术方案v0.4》《执行方案v0.4》、仓库 AGENTS.md，以及《需求变更单（2026-11-18）》。正文随后并入这些文档；并入之前，冲突处以本变更单为准。

不变的部分：形态（器械认证版的Claude Code）、两个Agent、Agent内核（Pi）、项目工作区、资料库、三种权限模式本身、八部分审核卡、审批只接受浏览器请求、预算与计量、审计、执行记录不含正文、分期和V1的范围（下文另有说明的除外）。

1 变更内容

1.1 主力模型改为本地部署的DeepSeek

  1. 注册Agent和维护Agent的主模型（主Agent、子Agent）改为公司本地部署的 DeepSeek V4.1 Flash（无损版），运行在公司两台Mac Studio（M3 Ultra）上，MLX架构，内网访问。
  2. 模型网关增加本地模型的接入：OpenAI兼容接口，地址和模型名写在模型配置中，不写死在代码里；本地模型可以处理任何数据级别（含保密）。
  3. 本地模型暂不接入（X4）。开发期用OpenRouter上的模型模拟本地主模型：优先选OpenRouter上与本地部署同系列的DeepSeek模型，使评测结果尽量接近本地；没有同系列模型时选能力相近的开源模型，记入决定记录。本地模型的真实地址到位后再切换。
  4. 模型比选（PR-29、PR-37）把本地DeepSeek列为主模型的必选候选，重点测长链路工具调用的稳定性（连续多步调用工具、参数格式、按工具报错自我修正）。比选结论如本地模型达不到技能评测要求，交Lan决定，不自行改回闭源主模型。
  5. 外部模型（OpenRouter上的GPT等顶级模型）不再作为主Agent，改为下面1.2的工具。

1.2 外部模型作为Agent的工具

新增工具「外部模型协作」（建议名 consult_external_model）。这个工具是给Agent用的：什么时候用、用哪个模型、做什么，由Agent自己决定，不需要人批准（1.3的例外情况除外）。

用途不限于搜索，凡本地模型做不好的都可以交给它，例如：

类型例子
联网检索与核实查最新的FDA指南、法规修订、标准认可清单、召回和不良事件
复杂推理与分析实质等同论证是否成立、申报路径的选择、发补问题的应对思路
起草、改写、翻译英文申报文本、Cover letter、发补答复的初稿或润色
第二意见审阅本地模型写的稿子或结论，指出问题

发送内容的控制（唯一的硬性限制：保密内容不出公司）

  1. Agent可以把需要的内容一起发出去（问题、草稿段落、内部资料摘录），不限于一句问题。
  2. 系统按发送内容的数据级别处理：
    • 公开、内部：发送前做出网检查（第3条），通过后自动发送；
    • 保密：原文不出公司。由本地模型先把保密信息替换成代号（例如未公开的产品名换成「产品A」、客户名换成「客户1」），替换后的内容再做出网检查，通过后发送；结果返回后在本地换回原名。替换后的检查仍不通过，就拒绝发送，告诉Agent原因，由Agent换一种问法或改用本地模型完成。
    • 数据级别按来源判断：发送内容中引用、摘录了哪些资料，就取其中最高的级别；不能确定来源时，按本次对话读过的资料的最高级别处理。
  3. 出网检查在本地完成，不向外发送任何内容：
    • 程序检查：与保密资料原文的重合片段；保密词表（未公开的产品代号、客户名、价格、合同条款等，由注册人员维护）；
    • 本地模型检查：判断内容中是否带出了公司的保密信息。
  4. 每次调用发出的全文和返回的全文都存档，可按对话、日期查看；每天生成一份「今日外发清单」，进入日摘要。
  5. 外部模型服务商：模型网关对每个外部请求强制要求「不用于训练」和「零数据保留」（OpenRouter的服务商数据策略，参数名开发时按OpenRouter当前文档核对）；不满足的服务商不使用。

结果的使用

  1. 外部模型的结果直接作为Agent的工作依据，不标注「未核实」，也不要求人逐条确认。
  2. 法规、标准、指南这类事实性结论，外部模型要同时返回出处链接和原文摘录。系统自动核对：用网页工具取回出处原文并存档，检查摘录是否确实出现在原文中（复用V1逐字核对的机制）。
    • 核对通过：结论作为有出处的事实使用，审核卡和证据查看页显示出处；
    • 核对失败（链接打不开、原文中没有该摘录）：Agent重新查询或换一个外部模型交叉核实，不把未通过核对的说法写成事实。
  3. 外部模型和网页返回的内容只作为资料交给Agent，不作为指令：不改变Agent的权限，不触发写入或外发，不能越过1.3中由人完成的事。

预算：外部模型协作单独计量，设每次、每日、每月上限；超过上限时停止调用并提醒负责人，不改为逐次审批。

1.3 Agent在公司内部放开，对外仍由人完成

  1. 新对话的默认权限模式改为「完全允许」（原为「请求批准」）。三种模式和切换方式不变，人仍可以把某个对话切到「请求批准」或「只读」。
  2. 完全允许模式下，以下事情Agent直接做，不再先请人批准：读写工作区、写改业务记录（台账、提醒等）、在沙箱中运行代码、查内部资料、调用外部模型、联网检索和下载、给内部同事发资料请求和催办。改错的靠工作区版本、业务记录的原值保存、事务撤销和审计记录兜底。
  3. 过程中只在以下情况请人批准：
    • 调用外部模型时，内容含保密资料且本地替换后的检查未通过，而Agent认为确实需要发出（默认拒绝，见1.2）；
    • 发往公司外部的消息（逐条生成提案，与原来一致）。
  4. 不变：监管门户提交、缴费、签署、向监管机构或客户发送正式文件只能由人完成；真值字段只由人写；最终结果交人在审核卡上审核；风险接受、超预算和需要管理层决定的事项交人决定。

1.4 Agent的联网能力

Agent本身可以上网，方式是调用后端的工具，由后端经出网代理代为访问：

工具做什么变化
网页工具（web_search、web_fetch）搜索、打开网页、下载文件（PDF等）存入项目工作区和资料库可读取任意公开网站，不限于官方来源。来源类型（官方、扩展、一般网站）照常记录，作为出处信息，不限制使用。检索词和请求的网址也经过1.2的出网检查
外部模型协作见1.2新增
官方数据工具（openFDA、GUDID等）查官方数据库不变

代码沙箱：Agent写的代码在沙箱中运行。沙箱从「完全不能联网」改为「只经出网代理访问沙箱白名单」：

  • 沙箱白名单：官方法规和数据网站（fda.gov、accessdata.fda.gov、api.fda.gov、ecfr.gov、federalregister.gov、regulations.gov、accessgudid.nlm.nih.gov等）和Python包的下载源；常用的包预先装进沙箱镜像；
  • 沙箱仍然没有凭据，不能访问内部网络中的其他服务；
  • 沙箱不能访问任意网站，原因是代码发出的内容不经过出网检查。需要白名单以外的网站时，由Agent用网页工具获取，再交给沙箱中的代码处理；
  • 新增沙箱白名单地址，由Lan确认后写入配置。

1.5 出网控制提前完成

「Agent在内部放开」的前提是数据只能经受控的出口离开公司，因此PR-13提前到主路径走通之后的第一批，并作为代码沙箱（PR-22）、本地模型接入之后的外部模型协作工具的前置条件：

  1. 后端接口服务和后台进程也在Docker中运行，只连接没有出口的内部网络；唯一能访问外网的是出网代理（和网页抓取服务所在的抓取网段）。「只能经代理出网」由网络结构保证，不只依靠代码约定。
  2. 开发时在Windows上直接运行的Node进程，仍按现状只能靠代码约定；PR-13在PR说明中写明开发方式和部署方式的差别。
  3. 本地模型（Mac Studio）的内网地址登记为内部地址，后端可直接访问，不经出网代理。
  4. 出网代理中写死的 openrouter.ai 地址（deploy/egress/hosts），在README中写明核对和更新的方法。

1.6 预算核账

现有账本在用量不明时停止真实模型调用（metering_incomplete），但没有核账后恢复的入口。新增命令 pnpm budget:reconcile：

  1. 输入账本编号、核对结果（已计费：实际金额和token数 / 未发送 / 按预占金额计费）和核对依据；
  2. 在一个事务中更新账本、写审计记录；
  3. 账本中没有其他不明用量时，才清除停止状态；
  4. 先写测试，不放宽其他预算检查。

PR-D5 外部结论的出处核对

  • 依赖：PR-40、PR-D4。
  • 范围：外部模型返回事实性结论时要求附出处链接和原文摘录；系统用 web_fetch 取回并存档，按V1机制逐字核对摘录；核对结果交给Agent，核对通过的结论在审核卡和证据查看页显示出处；核对失败时Agent重查或交叉核实。
