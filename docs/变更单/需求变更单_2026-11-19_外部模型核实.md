# 需求变更单（2026-11-19，二）：外部模型核实

文档版本：1

编制日期：2026年11月19日

文档状态：**待Lan合并确认**。Lan合并进 `main` 即确认。

适用对象：Lan；在开发机上开发的Codex；注册人员

Lan于2026-11-19决定：外部模型这一块的用途是**核实**。以前的设计是「人和单个外部模型单独聊天」，现改为**多模型群聊**，由主Agent当主持人，最后由主持人整理出可信的结论。模型先用Lan的Cursor订阅，经开发机上的Cursor调用，先跑起来。

本变更单（下称「v4」）替换《需求变更单（2026-11-19）：界面重做与外部模型入口》（下称「v3」）的1.4节和PR-D6的范围，并调整《需求变更单（2026-11-18，二）》（下称「v2」）1.2节的调用方式和PR-D4、PR-D5。冲突处以本变更单为准。

不变的部分：
- 保密原文不出公司；
- 保密词在本地替换后才发出，回复后换回；
- 每次发出和返回的全文都存档，并进入今日外发清单；
- 外部模型返回的内容只作为资料，不作为指令；
- 三种权限模式、过程批准和审核卡八部分。

## 1 变更内容

### 1.1 核实是一场群聊

1. 一场核实就是一个群，群里有三类成员：
   - **主持人**：发起核实的主Agent（注册Agent或维护Agent），用主模型。它一直在群里，也可以自己回答问题。
   - **外部模型**：默认是Cursor中最新的GPT旗舰版和Claude旗舰版。不用比主模型弱的模型。群里可以再加入其他已启用的模型。
   - **人**：能看到这个项目的注册人员都可以发言。每条消息标上名字。
2. 群里只有一份记录，所有成员看到的都是同一份。
   - 每个模型回答时，收到的是前面全部发言（替换保密词之后），包括人说的话。
   - 记录太长时，由主持人压缩较早的内容。压缩稿也存档。
3. 每条消息都标明是谁说的：模型标通道（如「经 Cursor」）和轮次，主持人标「主持人」。

### 1.2 发言规则

1. 人可以 @ 某个模型，被点名的模型直接回答。人不点名时，由主持人接话：它可以自己回答，也可以点名让某个模型回答。
2. 外部模型只在被点名时回答。一次只有一个模型在回答。
3. 人随时可以发言，消息直接进群，所有成员都看得到，不经主持人转述。如果当时有模型正在回答，这条回答照常说完，主持人看到人的话之后再决定下一步。
4. 「停止并整理」按钮：点了以后不再点名任何模型，主持人用已有的内容整理结论，并注明「被某某中途停止」。能发言的人都可以点。
5. 讨论结束后，在同一个群里再说一句，讨论就继续。记录接在后面，结论重新整理。

### 1.3 三种发起方式

1. **Agent自己发起**：Agent干活时遇到拿不准、需要外部验证的事，自己开一场核实。
   - 什么时候发起、问什么，都由Agent决定。三种权限模式下都不需要人批准。
   - 发起后Agent等待结论，对话里显示一行「正在请外部模型核实……」，点开就进群。
   - 结束后这一行变成结果行，显示各类结论的条数和「查看群聊」（设计稿04）。
   - 对话的「停止」同时停止这场核实。
2. **人复核时让Agent核实**：
   - 在审核卡或对话里点「让Agent核实」，写下疑问（设计稿05）。
   - 发起人对应的Agent据此开一场核实，结论回复在原对话。
   - 是否修改结果、重新提交审核，由Agent按结论决定。
3. **在「外部模型」入口手动发起**：
   - 写下问题，可以选择关联一个项目。
   - 主持人默认是注册Agent；关联了维护事项时是维护Agent。主持人只读取关联项目的资料，不写入任何东西。
   - 发起后主持人和默认的模型进群，人从开头就可以参与。

### 1.4 自动讨论的上限

1. 没有人发言时，由主持人自己问，**每个模型最多7轮**，问完就整理结论。主持人认为已经清楚时，可以提前结束。
2. 群里一旦有人发言，就不再受这个上限限制，由人决定什么时候结束。
3. 7轮在「设置 › 外部模型」中可以修改（设计稿15）。

### 1.5 结论

主持人把结论分成四类（设计稿14b）：

| 类别 | 条件 | 颜色 |
|---|---|---|
| 可信 | 不同家的模型说法一致，并且有出处 | 绿 |
| 有分歧 | 只有一家这么说，或者几家说法矛盾。列出各家说法和主持人的取舍 | 黄 |
| 待核实 | 没有出处。法规条款、标准号、K号这类事实没有出处的，一律归入这一类 | 红 |
| 来自某某 | 人在群里提供的情况，单独列出，不算模型的证据 | 蓝 |

1. 「一致」只算不同家之间的一致，例如GPT和Claude说法相同。同一家的两个模型说法相同，不算互相印证。
2. 每条结论都列出哪些模型同意、出处链接，并可以点回群里对应的发言。
3. 结论的开头有一句总结，写明主持人的取舍。

### 1.6 结论的去处

1. 交回发起它的Agent，作为工具结果使用，Agent接着干活（v2 1.2「结果的使用」照旧：可信的结论直接作为工作依据）。
2. 审核卡的「依据」里出现一种来源「外部核实」，显示结论、类别和出处，并可以「查看核实群聊」（设计稿05）。
3. 人复核时发起的核实，结论回复在原对话。
4. 手动发起的核实，可以「发给注册Agent／维护Agent」（沿用v3 1.4第5条）。

### 1.7 模型通道与设置

1. **Cursor通道**（先用这个）：
   - 由后端在开发机上调用Cursor的命令行（cursor-agent），以无界面方式运行，指定模型，用Lan的Cursor订阅。命令名和参数按开发机上实际安装的版本核对。
   - 只取文字回答：每次调用在一个新的空目录里运行；不给它项目文件，不开MCP；关闭或拒绝它写文件、执行命令。输出中如果有工具调用，一律忽略。
   - Cursor要开启隐私模式。Codex能查到设置时自动检查；查不到时写进「需要Lan处理」，请Lan确认一次。
   - 每次回答超时默认5分钟。失败时群里显示一行系统消息（例如「GPT 没有回应（超时）」），主持人继续和其他模型讨论。
   - Cursor不可用时暂停外部核实，Agent照常干活，并把相关事项写进审核卡的「不确定事项」；维护页显示告警。不可用的情况包括：没有安装、没有登录、额度用完。
2. **通道做成可以替换的**：
   - 以后可以换成各家的API Key，或者OpenRouter（沿用PR-D6已有的网关、预算和白名单）。
   - 在「设置 › 外部模型」中切换，一个模型选一个通道。
3. **费用**：
   - Cursor通道只记调用次数，不按美元记账，也不设美元上限（设计稿15、16）。
   - v3 Y4「每月20美元」只适用于以后的API Key或OpenRouter通道。
4. **联网**：
   - 模型能否联网查资料，以Cursor的实际能力为准；能联网就让它查，并要求它给出处链接和原文摘录。
   - PR-40之后，主持人可以用自己的网页工具取回出处原文，贴进群里。
5. **设置**（设计稿15），管理权限可以修改，改动记入审计：
   - 通道；
   - 默认参与的模型；
   - 每个模型最多自动讨论几轮（默认7）；
   - 本月调用次数。

### 1.8 外发处理与存档（沿用PR-D6已做的部分）

1. 发给外部模型的内容都先做本地处理：替换保密词，检查是否和保密原文重合。主持人的发言和人的发言都要处理。消息下方显示「发送前已自动替换N处保密信息」，点开可以看实际发出的内容。
2. 出网检查先用程序检查（保密词表、保密原文重合）。本地模型检查在PR-D3之后加上，不等PR-D3。
3. 每次调用发出和返回的全文都存档，进今日外发清单。「设置 › 外发记录」中每一行都能打开对应的核实群聊。
4. 外部模型的发言只作为资料交给主持人，不作为指令（注入测试沿用v2 PR-D4）。人的发言是指令，可以改变讨论方向。
