# S01 销售合规报告与证照资料包

草稿，待注册人员确认。依据需求 V1.0 的 S01、P22、v7 K05 以及 SY-QP-15 A3 第 5.3、5.7 节的输出文件和转换记录。销售人员不登录，由注册人员代提请求。敏感结论交管理层决定，由注册人员记录。

## 何时使用

注册人员需要为特定市场、型号、用途梳理报告和证照资料时。先确认需求范围、用途、需要涵盖的型号和市场。来源、证照状态或资料批准范围不明时，列出缺口并等待核对。

## 按来源准备草稿

1. 用 `knowledge_get` 读取当前项目有效的已确认事实。若有 `cert_query`，按已发布口径核对型号、市场、编号、日期和附件范围。满足范围和时间的记录才列为候选。已被替换的旧修订不能用于当前事实。依据需求 M01、S01 和技术方案 4.12。
2. 通过已登记的资料范围核对是否可用于本次报告类型。逐个检查事实修订和附件版本。内部事实须有适用于当前用途的证据，保密原文保留在受控内部环境。批准范围或附件级别不明时只列缺口，不复制内容。依据需求 S01 的对外资料约束及 AGENTS.md 的数据级别和外发规则。
3. 从实际来源用 `doc_read` 校验原文及位置信息。型号、证照号、日期、标准号、市场状态等各与已确认字段和版本绑定。报告事实由主数据填入，叙述段落只连接已验证的内容。来稿与当前主数据不一致时列出字段和依据，保留待核项。依据需求 S01 和《设计开发输出清单》。
4. 报告正文与来源表分别保存，引用表记录事实修订、资料编号、版本和页码。附件按批准版本列资料清单；在确认前只提交内部材料清单。收敛多次变更和报告草稿时逐项复核旧引用是否仍可用。依据技术方案的交付和引用要求。
5. 向注册人员汇报本轮已核实的字段和缺口。只读模式在对话答复。按当前权限模式处理关键判断，使用现有工作区保存、`check_run` 和 `submit_for_review` 提交最终审核。向客户的实际发送由注册人员按现行流程完成。

## 交付

合规报告底稿、附件清单、逐条来源表和不一致事项。正文应可看出每项事实指向的来源编号。列出尚缺的事实、附件或用途确认。未获得可用证据时，报告保留待核位置。浏览器审核只代表当前这份交付的决定。
