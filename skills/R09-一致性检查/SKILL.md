# R09 一致性检查

草稿，待注册人员确认。仅供开发环境测试，不可作为生产发布版本。

## 适用范围

核对已导入资料中的文字写法并列出有据可查的候选差异。本草稿只覆盖对比器械 K 号写法核对；不判断正确 K 号、不判定对比器械适用性、不替代法规与注册人员判断。发现超出范围的事项时，列入不确定事项并交人处理。

## 工作方法

先读取项目 AGENTS.md 与本技能，列出计划；搜索资料取得编号与定位，再用 doc_read 读取实际原文。搜索摘要、工作区草稿和模型记忆不能充当原文证据。

将不同写法分别记录为带资料编号、版本、页码和逐字摘录的陈述。Word 页码是抽取单元，不冒称纸面页码；OCR 低置信内容和原始 PDF 占位页须明确说明限制。两条证据可以来自同一页的不同完整引语；仅改变空白重复同一引语不增加证据数。

在工作副本起草文字核查报告，保留来源、差异和“待注册人员确认”的结论边界，保存成最新工作区版本。用 check_run 自查，再用 submit_for_review 提交。提交时每条引语须已在本对话成功的 doc_read 回执中完整出现；程序重跑 V1/V3，并按本元数据核验最少两条不同证据。

## 交付与审核

交付工作区中的核查报告及结构化结果，包含 `skill`、`workspaceVersion`、`conclusion`、`claims`、`evidence`、`decisions`、`missing`、`uncertain` 和 `nextStep`。每项过程判断列明事项、选择、备选、理由、出处和风险，判断中的原文同样须经过 `doc_read` 和 V1 检查。没有过程判断时传 `decisions: []`。K 号使用字符串，单位字段传 `null`。当前检查报告列出 V1 与 V3 的结果及 V2/V4/V5/V6/V7/V8 的未执行状态。

提交后等待浏览器审核卡的决定；对话中的“已批准”无效。通过只冻结本报告版本，不代表正确 K 号已获确认，也不代表已向监管机构提交。
